# VeriFrame

**A synthetic-media detection platform that tells you what it found, how confident it is, and why — never a bare "fake" or "real."**

VeriFrame analyses images and video for signs of AI generation or manipulation and reports a calibrated probability with an explicit uncertainty band, backed by visual evidence. It's built around a simple conviction: a detector that hands you a single word is asking you to trust a black box, and deepfake detectors are wrong often enough — especially on media unlike anything they were trained on — that a black box is the wrong interface for this problem.

One detection core, three surfaces: a web app, a Chrome extension, and a REST API.

---

## Why this exists

Deepfake detectors degrade hard the moment they see a generator they weren't trained on. A model reporting 97% AUC on its training benchmark can fall to 65–75% on real-world media a year later, and most tools never tell you that. VeriFrame is built to be honest about that gap rather than paper over it:

- **No binary verdict, ever.** Every result is a calibrated probability, an uncertainty band, and a plain-language label — never a "FAKE" or "REAL" stamp. The full band table lives in one file (`packages/core/src/bands.json`) and both the TypeScript and Python sides read it, so a threshold can't quietly drift between the API and the UI.
- **Every number ships with evidence.** A Grad-CAM heatmap, a per-frame timeline, a frequency-spectrum plot — a score with nothing to look at is treated as a failure, not a result.
- **Accuracy claims trace to a file, not a sentence.** The `/accuracy` page and every number in this README's evaluation section are rendered directly from `services/inference/eval/reports/`, generated by our own cross-dataset evaluation harness. There is no hardcoded accuracy figure anywhere in the codebase.
- **Privacy by default.** The extension never scans in the background — every analysis is one explicit click. Uploaded media is deleted after a 24-hour TTL. The cache layer stores perceptual hashes, never raw media.
- **Detection is advisory, not evidentiary.** Every report carries a non-dismissible footer saying so.

These aren't aspirational bullet points — they're enforced in code and covered by tests. See [`CLAUDE.md`](./CLAUDE.md) for the full set of non-negotiable principles this project is built around, and [`DECISIONS.md`](./DECISIONS.md) for the running log of the trade-offs made to hold them.

## How detection works

An upload goes through up to four independent evidence streams, fused with weights derived from measured validation performance — not hand-picked:

| Stream | What it looks at | Status |
|---|---|---|
| **A — Spatial** | A ViT classifier over detected faces, with test-time augmentation and Grad-CAM | ✅ |
| **B — Frequency** | DCT statistics, FFT power spectrum, noise-residual consistency, JPEG grid artifacts | ✅ |
| **C — Temporal** *(video only)* | Optical-flow discontinuity, blink analysis, head-pose jitter, rPPG (remote pulse) | ✅ evidence only — see below |
| **D — Provenance** | C2PA Content Credentials, EXIF/XMP integrity, generator self-identification | ✅ |

A valid, trusted C2PA manifest or a generator naming itself in metadata overrides the statistical streams outright — cryptographic and recorded facts beat inference from pixels. Stream C has no fusion weight yet: no video-labelled evaluation dataset exists to derive one from, so its four signals are reported as supporting evidence but cannot move the reported score, exactly the treatment Stream B had before it was calibrated.

## The honest evaluation

Every accuracy figure quoted anywhere in the product comes from `services/inference/eval/`, our own harness, run under a **mandatory cross-dataset protocol**: calibration is fitted on one corpus, every headline number is reported on a completely different, held-out one. In-dataset numbers — the ones most tools quote — are shown too, purely to make the gap visible.

The most recent run (n=1200 images per corpus) reported spatial-stream AUC of **0.663** and frequency-stream AUC of **0.589** on the held-out split — both far short of anything worth marketing, and reported anyway. Read the full write-up, including a real discrepancy the protocol surfaced between validation and cross-dataset performance, in [`services/inference/eval/README.md`](./services/inference/eval/README.md) and the dated reports alongside it.

## Structure

```
apps/web            Next.js 15 web app — upload, poll, evidence-backed report
apps/extension       Chrome MV3 extension (WXT) — in progress
services/inference    FastAPI + PyTorch/ONNX detection service, all four streams + eval harness
packages/core         Shared Zod schemas, band thresholds, fusion logic, client-side pHash
packages/ui           Shared React components (web + extension)
```

**Stack:** pnpm workspaces + Turborepo · Next.js 15 / TypeScript strict / Tailwind / TanStack Query · Python 3.11 / FastAPI / PyTorch / ONNX Runtime · PostgreSQL + Drizzle · Redis + BullMQ · S3-compatible storage (MinIO locally, R2 in production) · Clerk auth · Docker Compose

## Getting started

```bash
pnpm install
docker compose up -d      # Postgres, Redis, MinIO
pnpm typecheck && pnpm lint && pnpm test
```

Copy `.env.example` to `.env` and fill in values before running any service. The inference service has its own Python toolchain — see [`services/inference/README.md`](./services/inference/README.md) for setup, exactly how a score is produced, and the full configuration reference; [`apps/web/README.md`](./apps/web/README.md) covers the web app's data flow and retention model.

## Licensing discipline

Every third-party model, dataset, and detection-relevant dependency is checked against its actual upstream terms before it's wired in — not assumed. [`LICENSES.md`](./LICENSES.md) tracks what's in use, and, just as importantly, what was evaluated and **rejected**: an AGPL-licensed face detector, non-commercial-only model weights, and a lip-sync model trained on a BBC-restricted dataset all got turned away here rather than silently shipped.

This repository's own license is not yet finalized.

## Legal & ethics

VeriFrame detects manipulation; it does not identify or accuse people — there is no face recognition, no identity matching, no subject database. It is built to comply with India's DPDP Act 2023 and GDPR: data minimisation, a stated retention period, a deletion endpoint, and clear consent before any upload. Every report is explicit that a detection result is a signal for human review, not proof.
